— Privacy First

Zero access to your data.

The HIMER agent runs in a fully isolated sandbox. It only processes anonymized compute packages sent by the orchestrator. Cannot read your files, access your browser, or touch your bank account or passwords. Open-source, auditable, stoppable with one click.

What HIMER does NOT do

  • Does not access personal files, photos, or documents
  • Does not read passwords, cookies, or browser data
  • Does not collect browsing history or biometric data
  • Does not sell, transmit, or store your data to third parties
  • Does not run arbitrary code — only cryptographically signed containers
  • Does not access webcam, microphone, or peripheral devices

What HIMER does

  • Processes only anonymized mathematical compute packages
  • Runs in isolated sandbox (WebAssembly / container)
  • Reports only technical metrics: CPU, RAM, GFLOPS
  • Uses 1 internal HIMER ID for wallet (anonymous)
  • Open-source — agent code can be inspected anytime
  • Instant stop: one click and your node disconnects
— Technical Documentation

How HIMER works from the inside.

For those who want to understand the mechanics. Nothing hidden.

1. Proof-of-Compute (PoC)

Each node reports heartbeat at 1Hz to the orchestrator. For each assigned task, the node must return the result + a cryptographic hash of intermediate steps. The orchestrator verifies a random sample (5%) by re-computing on witness nodes. If results differ, the node loses trust score and is temporarily blacklisted.

2. Intelligent Job Assignment

The orchestrator scores nodes by: trustScore × GFLOPS / (load + 1). High-priority tasks go to top nodes. Redundant tasks (requiring consensus) are distributed geographically for resilience.

3. Unlimited Scaling

The backend uses delta updates (only changed nodes sent at 1Hz) and sampling (frontend displays 500 representative nodes + region aggregates). Thus, 100,000 active nodes = ~50KB/s on WebSocket.

4. Earnings Formula

Calculation is fully transparent. Every second your node is active, contribution is measured:

GFLOP-seconds= GFLOPS_node × (load / 100)
Gross generated= GFLOP-sec × $0.0001 × boost
Your share= Gross × user_share
Wallet updateautomatic, instant

5. Withdraw

Earnings accumulate every second. Minimum withdraw: $500. Processing fee: 2%. Payment via Stripe Connect (bank account, USD), with Stripe Identity verification for security. If you lose your HIMER password, hackers still cannot extract funds — Stripe requires separate 2FA confirmation.

— Privacy Policy

Privacy by Design.

Built from scratch with the principle: your data stays yours. Not just on paper — technically impossible to access.

Isolation Architecture

  • → Sandbox WebAssembly / Docker: Code executes in isolated environment, no access to host OS.
  • → Network whitelisting: Agent only communicates with HIMER servers. Any other connection blocked.
  • → Filesystem read-only: Agent cannot write or read files outside its own work folder.
  • → Open-source verifiable: Agent code is on GitHub. Anyone can audit, recompile, verify.

— About the Project

Why HIMER?

We live in an era where AI and intensive compute drive the economy. But processing power is concentrated in 5 companies (AWS, Azure, GCP, Oracle, Alibaba). High prices, dependency, and a missed opportunity for millions with powerful unused computers.

Our goal: Build an open alternative where anyone with a computer becomes a cloud provider. You earn from what's otherwise unused. Companies get cheap, fast compute.

We start small. Hundreds of nodes. Then thousands. Each contributor receives their share of value generated by their node. Together we build the largest DePIN alternative to centralized cloud.
